# ZEN履修登録Hub

ZEN大学の履修予定・履修済み科目、卒業要件、4年間の計画をブラウザで確認する非公式ツールです。

[公開サイト](https://zencoursehub.netlify.app/) · [設計と制約](docs/architecture.md) · [ブラウザQAの記録](docs/qa/)

## 解決する課題

科目の検索、履修状況、卒業要件の内訳、年度をまたぐ計画を行き来しながら確認できるようにします。275科目のカタログを使い、ユーザーの履修データはブラウザのlocalStorageで管理します。大学の正式な履修登録は行いません。

## 主な機能

- 科目名・教員名の検索、学年・開講Q・分野・必修区分の絞り込みと並べ替え
- 履修予定・履修済みの管理、取得単位と卒業要件の内訳表示
- カリキュラムマップの移動・拡大縮小・検索・履修操作
- 4年計画の配置、前提条件・配置上の問題・卒業要件の見通しの確認
- 2027年2月の試験候補の一覧・検索・日時重複の注意表示
- 科目情報を引き継いだ報告フォーム

## 技術構成

HTML / CSS / JavaScriptで構成する静的アプリです。実行時のパッケージ依存はありません。DOMを扱うコントローラーと、卒業要件・配置条件・履修遷移などの純粋な判定処理を分離しています。ビルド・検証にNode.js、PostCSS、ESLint、Prettier、Node標準のテストランナーを使用します。

大きなUIフレームワークへの置き換えを前提にせず、既存のカタログID・保存形式・公開URLを維持して責務を分けています。ブラウザのスクリプトとNodeテストの双方で利用するモジュールは、小さな公開APIを持ちます。

## 開発を始める

Node.js 24推奨（22.13以上）。依存関係はロックファイルで固定します。

```sh
git clone https://github.com/tanzana7/zen-course-hub.git
cd zen-course-hub
npm ci
npm run dev
```

`http://127.0.0.1:4173`を開きます。HTML・JavaScript・スタイルの変更を検知して再ビルドするため、ブラウザを再読み込みして確認できます。ポートは`ZEN_PORT`環境変数で変更できます。

`file://`でHTMLを直接開くとJSONを取得できません。開発サーバーは公開対象のファイルだけを配信します。

## 検証

```sh
npm run check       # Lint、整形確認、公開ビルド、全自動テスト
npm run qa:exam     # 試験日程・報告フォームの実ブラウザQA
npm run qa:map      # マップ・履修保存・卒業要件・4年計画の回帰QA
```

ブラウザQAは専用の一時プロファイルを生成し、1280px・390px等で操作します。普段使うブラウザや本番サイトのデータには接続しません。Windowsでは標準のChromeインストール先を利用し、他の環境では`CHROME_PATH`でChromeの実行ファイルを指定できます。`ZEN_MAP_QA_SERVE_DIST=1`を設定すると公開用ビルドを対象にします。

```sh
npm run test:coverage # 純粋な判定・保存処理のカバレッジ
npm run format     # ソースの整形
npm run build      # netlify-dist/へ公開ファイルを出力
```

GitHub ActionsではLinux・Windowsの品質チェックとWindowsのブラウザQAを実行します。CIからのデプロイ処理はありません。

## ディレクトリ

| 場所                                                | 責務                                                                              |
| --------------------------------------------------- | --------------------------------------------------------------------------------- |
| `app.js`                                            | 状態の初期化、機能の接続、必須・任意データの反映                                  |
| `src/features/`                                     | 履修管理、科目探索、卒業要件表示、4年計画、埋め込みマップ、ナビゲーション、ヘルプ |
| `src/domain/`                                       | 保存先やDOMに依存しない履修状態遷移                                               |
| `src/data/`                                         | データの取得・正規化・検証・関係構築                                              |
| `src/styles/`                                       | スタイルの編集元。公開時は1つの`style.css`へ結合                                  |
| `graduation-requirements.js` / `simulator-rules.js` | 卒業要件・計画配置の判定                                                          |
| `quality-utils.js`                                  | 保存形式の検証、保存失敗時の復元、HTML・URLの安全な処理                           |
| `curriculum-map.js`                                 | 独立したカリキュラムマップのカメラ・操作・表示                                    |
| `exam-schedule.js` / `exam-feedback.js`             | 試験日程の判定と表示                                                              |
| `tests/`                                            | 判定、保存失敗、入力、公開ファイル、起動等のテスト                                |
| `scripts/`                                          | 公開ビルド、開発サーバー、ブラウザQA                                              |
| `docs/`                                             | 設計・データ照合・検証の記録                                                      |

`style.css`は生成ファイルです。直接編集せず、`src/styles/`を変更して`npm run build`を実行します。公開先への出力は許可リスト方式で、開発資料や元データを誤って配信しない構成です。

## データと制約

- 履修・計画データは端末のlocalStorageへ保存します。アカウント同期はありません。
- 保存が失敗した場合は元の値へ復元し、保存できた場合だけ画面の状態を確定します。復元まで失敗した場合は上書きを停止します。
- カタログに存在しない保存済みIDは、将来復元できるよう保持します。
- 試験日程は62科目・186候補の元データから、科目名が完全かつ一意に一致する59科目・177候補を対応付けています。残る3科目は未照合です。日程は変更される可能性があります。詳細は[照合記録](docs/exam-feedback-validation.md)を参照してください。
- 60/90列の意味、3候補の正式な区分、実際の開始時刻は断定しません。
- 報告フォームはNetlify Formsの静的POST構成です。Netlify側のフォーム検出設定とデプロイ後の受信確認が必要で、実受信は未検証です。ローカルでは送信を停止し、成功表示をしません。履修データを自動送信しません。
- Google Analyticsの利用、難易度データの出典は画面のフッターに記載しています。

卒業要件・履修可否の最終確認には、大学の公式情報・学生要覧・シラバス・Portalを利用してください。
